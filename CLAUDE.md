# Flaccy

Music player for FLAC and other local libraries, one product on four clients: iOS (iPhone only), macOS, watchOS and Linux (Rust + GTK). Server: flaccy-api (`services/flaccy`, Worker `flaccy-api.midgarcorp.cc`).

## Layout
- `App/`, `Features/<Feature>/` and `Resources/` iOS (shared with the Mac where the Mac target does not exclude a file), `Platforms/mac/` macOS, `Platforms/watch/` watchOS, `linux/` Rust client with `linux/shared/` (Rust mirror of FlaccyCore, builds without GStreamer).
- `Core/FlaccyCore/` shared Swift (nonisolated, Swift 6). Its second product `FlaccyEngine` (depends on GRDB, so the watch never links it) holds `DatabaseManager` with its records, `Track` and `PlaybackEngine`; `AudioPlayer` in `Features/Playback/` is the system glue (Now Playing, remote commands, scrobbling, stations) that the engine reaches through `PlaybackEngineHost`. `Tests/flaccyTests/`, `Tests/flaccyUITests/`, `Tests/flaccyMacUITests/`, `scripts/`, `project.yml`, `store/`, `metadata/`.
- `Platforms/mac/App/DebugDrive.swift` is the DEBUG-only window self-capture.

## Setup, build, test
- `cp App/Secrets.swift.example App/Secrets.swift` and fill the Last.fm key (https://www.last.fm/api/account/create). `Secrets.swift` is gitignored and never committed.
- `xcodegen generate` writes the gitignored `flaccy.xcodeproj` from `project.yml` (templates in `build/xcodegen/midgar-app.yml`). Build `flaccy`, `flaccyMac` or `flaccyWatch Watch App` from it. `midgar ship` runs XcodeGen itself.
- From the Linux box: `scripts/build-mac.sh [ios|mac|watch]` rsyncs and builds on the Mac over Tailscale, then runs `scripts/check-strings.py`.
- Shared logic, both sides: `bash scripts/test-shared.sh`. Rust only: `cargo test -p flaccy-shared --manifest-path linux/Cargo.toml` (the `flaccy` crate does not build on the Mac, no `gstreamer-1.0`).
- Watch transcoder: `bash scripts/watch-transcode-harness/run.sh`. Watch catalog: `python3 scripts/check-strings.py --watch build/dd-watch-main`.
- Deploy flaccy-api: `npx wrangler@4.149.0 deploy` (the version pinned in the repo fails against Cloudflare's current API).
- Mac self-capture: launch `Flaccy.app/Contents/MacOS/Flaccy <flags> &` directly (`open --args` drops flags); flags include `--shot-queue`, `--shot-nowplaying-lyrics`, `--shot-queue-deep`, `--shot-equalizer simple|advanced`, `--shot-paywall`, `--window-size WxH`.
- iOS exercises and screenshots: `--seed-screenshots`, `FLACCY_ROUTE=<screen>`, `--exercise-sample`, `--exercise-equalizer`, `--exercise-watch-sync` (fresh simulator pair), `--exercise-receive` (watch), `--exercise-watch-bgtask` (device), `--exercise-playlist-cover` (Mac), `--trial-day N`. They log PASS/FAIL to the app log.
- Linux demo hooks, against throwaway XDG dirs: `FLACCY_DEMO=1` with `FLACCY_DEMO_SAMPLE`, `FLACCY_DEMO_EQ`, `FLACCY_DEMO_EQ_UI`, `FLACCY_DEMO_DETAIL`, `FLACCY_DEMO_PLAYLIST_PAGE`, `FLACCY_DEMO_PLAYLIST_COVER`, `FLACCY_DEMO_SHARE='Artist|Title'`, `FLACCY_DEMO_SCRUB_DRILL=1`. Measure idle cost with `FLACCY_FRAME_STATS=1`, a nested `kwin_wayland --virtual` and `nvidia-smi pmon`, never Xvfb.

## Rules that break things
- Parity: a behavior change on one client lands on all four in the same unit of work, or the gap is recorded in the notes. Put shared logic in `FlaccyCore` and mirror it in `linux/shared/`, with tests on both sides. Pure shared logic can be tested standalone on Linux via swiftly.
- Push before driving `scripts/build-mac.sh` from either machine: it mirrors arch onto the Mac with `rsync --delete`, so Mac-only work is lost. Release only from a pushed `master`. Rsyncing back, exclude `build`, `.build`, `DerivedData`.
- Never `pkill -x flaccy` on arch: the user's real instance shares the name. Kill the PID you started. Keep `pkill -f`/`pgrep -f` out of the Bash tool's own command line. Build and bench into `~/.cache`, not `/tmp`.
- MidgarKit comes from `packages/MidgarKit` by path (D15). `FlaccyMidgar` (iOS, Mac) builds the Midgar ID (keychain groups `$(AppIdentifierPrefix)$(PRODUCT_BUNDLE_IDENTIFIER)` then `$(AppIdentifierPrefix)cc.midgarcorp.shared`, no App Attest entitlement), the portal and MidgarSignals, and runs first from the app delegates. The watch uses none of it.
- Purchases go through `MidgarStore` (`engine = "rc-observer"`, D2): `FlaccyMidgar.store` buys, finishes and reports to the ledger the products in `FlaccyProducts`, and `PurchaseManager` gates on its `pro` entitlement. `RevenueCatObserver` keeps RevenueCat in observer mode for its dashboard and the `PurchaseFunnel` attributes; it never decides access. iOS and Mac are separate SKUs (`com.midgarcorp.flaccy.{pro.yearly,lifetime,lifetime.welcome}`, `com.midgarcorp.flaccy.mac.{pro.yearly,lifetime,lifetime.welcome}`) in separate RC projects (iOS `proj69262cb7`, macOS `proj5ef1fe52`), never a universal purchase. `Tests/flaccyTests/PurchaseStoreKitTests` buys each plan against `Flaccy.storekit`. Never compare against `.purchased` alone: match `.purchased(.lifetime)`/`.purchased(.yearly)` or use `isPurchased`. Linux has no purchase.
- Trial: the Keychain start is stamped at the first play of the person's own music, never at install, and ignores the sample album. `TrialClock` queries stay byte-identical (service + account only, add-only `SecItemAdd`) or every shipped user gets a fresh trial. All trial dates go through `FlaccyCore.TrialRunway`. Never auto-pop a paywall (App Review rejects it). Reminders need the in-app consent alert (Guideline 4.5.4). Prices come from `StoreProduct.price`, never strings.
- Last.fm: the shared secret lives only in the flaccy-api Worker (`LASTFM_SECRET`). Every signed call (`auth.getToken`, `auth.getSession`, `track.scrobble`, `track.updateNowPlaying`, `track.love`, `track.unlove`) asks `POST /v1/lastfm/sign` with the `X-Device-ID`; read-only methods stay unsigned. Session keys stay on device. Never put the secret in a client.
- AI: the app holds no key. `FlaccyAPIClient` is the only code that talks to flaccy-api (`https://api.midgarcorp.cc/v1/flaccy/...`, `X-App-ID: flaccy`). The Worker alone picks the model (secret `ANTHROPIC_API_KEY`) and refunds quota on upstream failures. Caps are `DEVICE_DAILY_LIMIT`/`IP_DAILY_LIMIT`/`GLOBAL_DAILY_LIMIT` in `wrangler.jsonc`; the global cap is the spend ceiling. Do not route it through mako. Linux never calls the AI proxy.
- User's library: import never clobbers or duplicates (`.name.flaccy-part` then rename, same path and size counts as present, refuse before a byte moves if it will not fit). Gapless is always on, never add a toggle. Do not port Downloads or music video (yt-dlp) to the Apple clients (Guideline 5.2.3).
- Enrichment keys normalize identically in SQL and code (registered `flaccy_norm` function); normalize each half of a composite key separately. Albums group by release credit, not per-track artist. Scrobbles before 2002-01-01 UTC are undated.
- Strings: every compiled string must exist in `Resources/Localizable.xcstrings` and be translated. Keys use `%lld`/`%@`, never `%1$lld`. Edit the catalog only through `json.dumps(d, indent=2, ensure_ascii=False, sort_keys=True) + "\n"`.
- A new iOS-only file in `App/` or `Features/` must be added to the `flaccyMac` target's `excludes` in `project.yml` (paths relative to that source folder). Network access goes through a client in `App/Network/`, never `URLSession` in a view or service.
- Secrets: `LastFMService.configure(apiKey:)` copies the key from `Secrets` at launch. RevenueCat keys (`Secrets.revenueCatAPIKey`) are gitignored. `scripts/rc-setup.py ios|mac` reads `RC_SECRET_FLACCY_<IOS|MAC>`.
- Images are tracked with Git LFS: pushes need `git-lfs` on PATH, and a fresh clone or worktree needs `git lfs pull` before the art shows.

## Conventions
- Swift 6 language mode, strict concurrency, MainActor default isolation on Apple targets, warnings as errors in Release. A closure Apple calls on its own queue must not inherit MainActor: use a `nonisolated` function, `@Sendable` or `onMainActorSync`.
- Fully programmatic UIKit, MVVM, diffable data sources, UIStackView heavy, protocol-oriented, no storyboards or XIBs, iOS 18, thin view controllers. Persistence is GRDB (SQLite).
- Logging: `MidgarLog` only, never `print()`. `FlaccyLogging.configure()` names the file `Library/Logs/flaccy.log`. Categories are `MidgarLog.Category` constants in FlaccyCore.
- No comments or MARK statements; name things so they read clearly.
- Haptics on every interaction, per Apple's Human Interface Guidelines. Error toasts and empty states name what failed, the cause and the next step.
- Reviews: `ReviewPrompt` reports to `MidgarReviewPolicy` after real use.
